# Local security model

Top-level browser GET navigations to `/` and `/index.html` may open the public Console shell from another site. This exception requires Fetch Metadata identifying a document navigation; it never applies to `/v1/` API requests, subresources, or writes.

Agentree is a single-user local tool. It listens only on loopback. There is no account, password, admin bearer, browser session, cookie, pairing, or external authentication service. Requests without Authorization act as the human `local-admin`; this is an authority label in audit records, not proof of a particular physical person's presence. Existing admin-token files are unused and can be deleted.

The HTTP boundary checks Host against localhost/127.0.0.1 and the actual listening port to reject DNS rebinding. Origins must match the Gateway origin or an explicitly configured loopback Console development origin. Browser writes carrying Fetch Metadata require Origin; cross-site requests without Origin are rejected. These checks apply before human and native operations. CORS alone is not authorization. SSE uses the same origin checks without cookies. Non-browser local CLI requests may omit Origin. The default Vite origins trust code served on port 5173; set GATEWAY_CONSOLE_ORIGINS to an empty string when development is unnecessary.

Managed native sessions retain random bearer capabilities stored as hashes in SQLite. A bearer never becomes a human request, even if invalid. It binds activity ingestion, tool decisions, task claims and correction delivery to one session; agent workspace and branch limits still apply. Human HTTP access cannot submit observed activity without a session capability. Tokens and session state survive Gateway restart; ended sessions cannot resume active operations. Native credential files and the database must remain private to the OS user.

This does not sandbox malicious processes running as the user. Any local process can exercise human governance, create a new session, or access data permitted by the OS. A process able to read another session's token, inspect its environment, or modify SQLite can compromise its identity. Session credentials prevent impersonation through the API without that capability; they cannot protect against an attacker with equivalent filesystem/process access. Browser extensions, compromised trusted Console code, and local malware are outside this boundary. Origin headers can be forged by native clients, which are already trusted as local humans. No remote listener, reverse proxy exposure, shared multi-user machine isolation, or remote authentication is supported. Future remote access must introduce a separate human authentication boundary before exposing this API.

Use one data directory: AGENTREE_HOME, then GATEWAY_DATA_DIR, then ~/.local/share/agentree. `agentree` with no arguments starts a detached Gateway or connects to one whose health response identifies that exact database. The fixed port bind prevents duplicate listeners; a conflicting service or data directory fails explicitly. Logs go to gateway.log; stop the Gateway with SIGTERM. CLI subcommands retain direct SQLite access and their existing --db override. They do not start a daemon. Build both backend and Console before normal use; Vite development remains supported. Set AGENTREE_NO_OPEN=1 for headless startup. Nothing requires an account or network authentication.
