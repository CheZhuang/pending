## 目标与资料取舍

C 当前要交付的是 **Agentree 的 Harness 控制台**。Agentree 是项目名称，比赛主线仍然是：启动 CLI agent、显示真实流量、在执行前阻止违规动作、停止运行。人工审批补齐这条操作链。

依据：

- C 负责人当前确认的方向：Harness 控制台。
- 提供的旧版《C-控制台》：单页、会话泳道、事件详情、审批、Stop，可复用其交互目标。
- 仓库 README、现有 `packages/contracts` 和 `packages/core`：当前实现的事实依据。旧版 `/v1/decide`、`AgentEvent.seq`、`@harness/shared` 等尚不存在，不能照搬为已实现契约。
- 提供的新版 Task C 与对账结论：Scoped Context Sync、Human CLI、Merge 和 Demo 是另一组工作包。保留在后续扩展，不把它们默认为控制台第一版的前置条件。
- [A10 官方赛道说明](https://aws.scuacm.com/)的 Agent Harness 演示要求，以及 [Devpost](https://a10-x-aws-hack-26.devpost.com/)的提交要求。Devpost 当前列出的截止时间为 **2026-11-08 09:00 PST**；建议提前留出提交缓冲。

**需要团队对齐的范围差异：** 当前 README 仍写着“不做 graphical dashboard”，新版 Task C 的主目录为 `packages/sync`、`apps/cli`。本计划按 C 负责人当前明确的控制台目标提出 `packages/dashboard` 工作包；这个取舍需要在团队评审中同步到正式契约。本 PR 不直接重写 A/B 的任务或共享模型。

### C0：先确定对接点

本次文档完成不代表接口已冻结。C 可以开始 C1；真实连接和控制操作须依照 A/B 实际提供的服务开发。

| 能力 | 当前代码状况 | 后续对接责任与验收 |
| --- | --- | --- |
| 工作区、分支、会话注册 | `ApplicationService` 提供 `workspace`、`branches`、`createWorkspace`、`createBranch`、`registerSession` | A 暴露经授权的传输接口；B 把原生运行绑定到 Session；注册不代表已启动进程 |
| 会话列表与运行状态 | `Session` 有身份与分支信息，但无运行状态/退出状态；服务无会话列表方法 | A/B 定义运行生命周期与能力；C 展示真实状态，不能从最后一条事件猜测已停止 |
| 事件读取、历史与订阅 | 有 `NormalizedEvent` 和 `ingest`；`ApplicationService` 没有事件列表、游标或订阅方法 | A 提供授权读取与稳定游标；B 保证 source/nativeId 稳定；C 不访问 `SqliteStore` |
| 原生工具执行前拦截 | `executeControlled` 有执行前授权示例；README 明确它不控制原生 CLI 工具 | B 接实际执行前控制点；A 返回最终授权结果并审计；C 展示结果与来源 |
| 人工批准工具动作 | 当前 `Review` 绑定 `mergeId`，用于上下文合并 | A/B 另行明确工具审批请求、超时、取消、执行回执；不能用 Merge Review 冒充工具审批 |
| 停止运行 | 尚无停止方法、进程能力模型或已退出回执 | A 授权停止请求；B 停止受管理运行并回报结果；C 显示 stopping / stopped / failed 等确认后的状态 |
| Context / Merge 展示 | 有 `context`、`lookup`、`createMerge`、`review`、`resolveReview`、`applyMerge` | 放到后续协作扩展；review approved 不等于 merge applied |

需要 A/B 在真实联调前给出的最小约定：

1. **传输与身份**：服务地址、经认证的人类客户端方式、错误格式；浏览器提交的身份字段不能自行授予 human 权限。
2. **事件关联**：会话、运行、工具请求和审批各用什么 ID；请求与多个判断事件如何关联；哪些事件是 observed，哪些是 controlled。
3. **历史与恢复**：稳定排序键/游标、历史分页与订阅交接规则、重复事件标识、断线补拉方式。不要用时间戳独自充当恢复游标。
4. **工具审批**：等待与最终允许/拒绝的区别、有效期、重复提交/过期处理、批准后是否真正执行；不预设旧文档中的 90 秒。
5. **停止能力**：哪些运行支持停止、请求幂等性、失败和已退出回执；不能控制的会话要明确标记能力缺失。

### C1：假数据控制台骨架

建议目录为 `packages/dashboard`。先实现一页四个区域：

- 顶栏：Agentree、数据模式、连接状态、会话数、待处理数。
- 主区：每个会话一条泳道，显示运行状态与事件节点。
- 详情：工具名、关键参数、判断结果、原因、来源与时间。
- 操作区：待审批与停止入口，配合明确标注的模拟数据。

Mock 与真实 Gateway 在一个数据源适配层切换。C 可以先定义本地展示模型，但它不是 `packages/contracts` 的替代品；真实适配器负责映射已确认的公共契约。Mock 提供确定顺序、重置和手动推进，便于演示与后续验证。

验收：启动后能看到完整模拟序列；切换节点能查看详情；页面不会把模拟审批或模拟停止呈现为真实执行。第一版不增加路由、登录页面或设置页面；真实连接所需认证由 Gateway 对接方案提供。

后续 PR 必须加入实际可运行的启动脚本和命令。本计划不把尚未添加的 `pnpm dev:dashboard` 等命令当作现有能力。

### C2：实时事件与时间线

先在 Mock 中验证，再接真实读取接口：

- 使用明确的请求关联 ID，把请求、等待批准和最终结果显示为同一次动作；最终结果不能被迟到的等待事件覆盖。
- 已观察到动作与网关允许动作分开显示。`observed` 事件不能自动画成“已授权”。
- 历史与订阅交接使用后端提供的稳定游标，按稳定 ID 去重；重复、乱序、重连不会制造假节点或丢失节点。
- 点选节点展示完整详情，顶栏统计遵循去重后的状态；不支持的事件保留原始信息和中性显示。
- 断线时保留已有历史，明确提示离线，恢复后补齐数据。

验收：同一批事件重复发送两次只出现一份；等待变最终允许/拒绝；断开后新增事件，恢复时能补齐；未知结果不会被当作放行。

### C3：人工审批与 Stop

审批与停止都经过 Gateway 授权。按钮点击只表示请求已提交，最终状态以服务结果及执行回执为准。

- 审批卡片展示动作、参数、原因、适用会话和后端有效期。提交期间禁用重复操作。
- 对拒绝、过期、已被他人处理、无权限、网络失败提供可理解的提示，并刷新真实状态。
- Stop 前确认目标运行；请求发出后显示停止中，B 确认退出后才显示已停止。失败时允许重新读取状态。
- 对不支持执行前控制或停止的 adapter 明确显示能力，不能提供看似可用的假按钮。
- 网关审计记录应能关联请求、人类决策和最终结果。不要因为界面变绿就声称动作已执行。

验收：批准、拒绝、超时、重复点击、无权限、停止失败和成功都有可验证路径；被拒绝的操作在真实执行端没有副作用。

### C4：先跑通一条真实 Harness 路径

最小比赛演示顺序：

1. 用 B 的真实启动方式启动一个可控 CLI agent，在控制台看到运行与连接信息。启动入口可以先是命令行。
2. 执行一个允许的动作，展示请求、网关判断和结果。
3. 请求一个安全测试动作，例如向临时测试目录写标记文件；配置规则将其拒绝，展示原因，并确认文件未生成。
4. 请求另一个需要人工审批的测试动作；从控制台处理，验证最终执行结果及审计链。
5. 运行一个可持续输出的安全测试任务；点击 Stop，等待真实退出回执，确认停止后没有继续执行新动作。
6. 重新打开控制台，仍能读取本次运行的审计记录。

一个真实运行先满足 Harness 主线。仓库 README 的双运行时、协作同步与合并要求仍是另一组验收；单 agent Demo 通过不能标记整个 Agentree 项目完成。

验收同时需要 C 的操作流程、A 的授权和持久化记录、B 的实际执行/停止证据。Mock 录屏可作备用说明，但不能标为真实集成结果。

### C5：稳定与交付

优先保证大屏可读、空状态有指引、错误可恢复、Demo 可重复运行。暂缓复杂动画、自动回放和多页产品功能。

交付清单：

- README：环境要求、启动顺序、实际命令、验证步骤、已知能力限制。
- Demo 脚本：每一步操作、预期画面、怎样验证“未执行”和“已停止”。
- 提交素材：截图、约两分钟视频脚本、slides 提纲；对代码、架构和权限边界能作解释。
